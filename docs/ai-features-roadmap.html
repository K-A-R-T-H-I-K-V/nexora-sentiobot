AI Features Roadmap  /  built on a verified production foundation

From a RAG bot to an agent that understands, feels, remembers, and proves

The foundation is done: measured, hardened, deployed, fail-closed. Now the fun part. SentioBot means "I feel" in Latin, and right now it feels nothing. This roadmap turns a correct support bot into a product people remember, cheap and on-brand features first, every one measured so it never breaks what is underneath.

The rules every feature obeys

Token budget is the hard limit (~100K/day on Groq free, so prefer local/zero-token and the cheap 8B model). Anything touching answer quality is measured against the frozen 50-question set before it ships. Nothing may regress hit@5 0.913, the injection red-team, or the 10/10 cross-user denial suite, all CI-gated. Security travels with the feature: uploads and memory carry their own defense.

TIER 1

The Smarter Core

Fix the known weak spots and earn trust. Cheap, high-impact, makes everything downstream cleaner.

F1Intent-aware routing

~0 tokenshigh impactdo first

Retire the brittle keyword router (the word "warranty" wrongly sends a policy question to the tool path). A real classifier fixes a whole class of answers at once, and it is a flaw flagged since day-one recon.

How: embed the query with the local ONNX model, match to labeled intent prototype vectors (doc / order / warranty / ticket / chitchat / escalation). Zero-token, deterministic. A new node before the router; keep the old router behind a flag to A/B. Gate: beat the keyword router on a labeled routing set; no hit@5 drop.

F2Groundedness guard + source highlighting

~0 to smalltrust

Verify each answer is supported by the retrieved context and show a "Grounded" badge; highlight the exact source sentence behind each claim. Answers the one question every user and recruiter has: "how do I know it is not making this up?"

How: a verify step after generation (local NLI/overlap heuristic first, an 8B "is this supported?" call only if needed); add grounded + citations to the existing done SSE event; the frontend renders the badge + highlighted spans. Gate: the badge must track RAGAS faithfulness; never a false green.

F3Reranking (measure-first, optional)

~0 tokensoptional

Re-order retrieved passages with a local cross-encoder so the best context leads. May lift faithfulness, especially as the corpus grows.

How: a local ONNX reranker node between retrieve and generate, behind a flag. Honest risk: may NOT beat 0.913 on a small corpus. Ship only if it measurably wins on the frozen set. Do it only if retrieval is the next real bottleneck.
TIER 2

Emotional Intelligence

The differentiator, and the reason the app is called SentioBot. Mostly cheap (local / 8B), and the part people remember.

F4Sentiment & frustration awareness

~0 to smallflagshipon-brand

Detect the user's mood each turn, adapt tone, and when frustration crosses a threshold, proactively offer a human instead of making them ask. It delivers on the product's name and it is genuinely good support. "The bot noticed I was annoyed and got me to a human" is a story.

How: a sentiment node (local classifier or 8B label+score); a running frustration signal in state feeds the prompt ("be concise, acknowledge, offer a human"); a threshold triggers escalation. Gate: detect accurately, escalate on frustrated cases and NOT on calm ones (a false escalation is annoying). Subtle: never announce "you seem angry," just adapt.

F5Clarify before answering

~0 tokenshuman-like

When a query is ambiguous or missing a needed detail, ask ONE targeted question instead of guessing. The difference between a form and a conversation, and it cuts wrong answers.

How: a slot-check keyed to the F1 intent (warranty needs a serial; resolve from the user profile first, ask only if truly unknown). A clarify branch in the graph. Bias toward resolving from context; at most one question.

F6Long-term user memory

small, recurringpersonalization

Remember durable facts across sessions (products, past issues, preferences) and be proactive: "Last time your Thermostat Pro had a pairing issue, is that resolved?" The biggest jump in perceived intelligence, a concierge instead of a kiosk.

How: a user_memory table under the SAME fail-closed RLS (a user's memory is theirs only); summarize-and-store on conversation END (one 8B call, budgeted, not per turn); load top facts at session start. Guards: only store facts traceable to the user or a tool (never model guesses); a "what SentioBot remembers about me" panel to view/clear, itself a trust feature.
TIER 3

Multimodal & Voice

The wow factor. One is nearly free (Groq hosts Whisper); one is the big, deliberate finale.

F7Voice mode

cheap (Whisper)demos brilliantly

Press the mic, speak, get a streamed answer read back. High cool-factor, real accessibility win, and it fits the stack almost for free.

How: browser captures audio, a /voice/transcribe endpoint runs Groq whisper-large-v3, the transcript flows into the EXISTING chat pipeline unchanged, browser SpeechSynthesis reads the answer back (zero cost). Text chat stays the default, so nothing regresses.

F8Multimodal RAG (see the manual, and your device)

higher costmost impressivedo last

Ingest diagrams from the manuals ("show me the wiring diagram"), and let a user upload a PHOTO of their device ("that blinking red LED means..."). Support is deeply visual; this unlocks questions a text bot cannot touch.

How: a Groq vision model + caption/embed manual images for retrieval + an image-upload path. Carries its own security: user uploads reopen the INDIRECT-injection surface, so text in an uploaded image is DATA, never instructions, the injection defense must be proven on this path before it ships. Budget vision tokens carefully. The finale, once the core is excellent.
TIER 4

Agentic Expansion

It does more, and it learns from itself.

F9More real actions

minimal

New tools: start a return/RMA, schedule a callback, recommend a compatible product for what the user owns.

How: each is a new LangGraph tool + a Supabase table under RLS, using the ContextVar user_id pattern (never trust the LLM for identity). Every new tool inherits the fail-closed pattern and gets a denial-suite case.

F10Self-improving loop

cheap, batchedcloses the loop

Mine thumbs-down and low-groundedness answers to surface the questions SentioBot answers badly, a prioritized list for corpus or golden-set expansion. It connects the eval harness you built back to the product.

How: an analytics query + a clustering/summarization pass over negative-feedback queries, surfaced in an admin dashboard. Pairs with feedback volume.
ORDER

Recommended build sequence

Front-load the cheap, high-impact, on-brand wins; defer the expensive, heavy ones. Best cool-factor per day of work, and it fits the token budget.

1F1 Intent routing 2F2 Grounded + citations 3F4 Sentiment/escalate 4F5 Clarify 5F7 Voice 6F6 Memory 7F3 Rerank (if it wins) 8F9 / F10 tools + loop 9F8 Multimodal (finale)

The discipline stays, even for features

Each feature is a normal increment: planner ratifies the design and gate, builder builds behind a flag and measures against the frozen baseline, reviewer re-runs the gate and tries to break it. It ships only if it improves what it targets AND regresses nothing (hit@5 0.913, injection containment, 10/10 authz). Every feature adds a learnings entry so the "why" is kept, not just the "what."
